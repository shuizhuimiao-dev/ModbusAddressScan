# 485 扫描（Modbus 从站地址扫描工具）

一个基于 WinForms（.NET Framework 4.7.2）的 Windows 小工具，用于通过 **RS-485 串口** 或 **TCP 网络** 逐地址扫描 Modbus RTU 从站：依次向地址 1~255 发送“读保持寄存器”请求，并把收到的应答以十六进制显示出来，方便快速确认总线上有哪些从站地址在线。

## 功能特点

- 支持两种通信方式，二者互斥（同一时间只能使用一种）：
  - **串口**：8 位数据位、1 位停止位、无校验、无流控（8-N-1）
  - **网口**：`TCP Client` / `TCP Server`
    - `TCP Client`：主动连接到指定 IP 和端口（常用于串口服务器/透传模块）
    - `TCP Server`：在本机 IP 上监听端口，等待设备或透传模块接入
- 可设置要读取的**输入寄存器 ID**（0–65535）
- 可设置**扫描间隔**（30–2000 ms，默认 80 ms）
- 扫描时状态栏实时提示当前扫描到的地址，扫描完成后自动停止（地址上限 255）
- 接收区以十六进制显示数据，并在每一帧后追加解析出的从站地址
- 支持一键清除接收区数据

## 运行环境

- Windows（WinForms）
- .NET Framework 4.7.2（或更高兼容版本）
- 使用 Visual Studio 2017 及以上版本打开 `485扫描.sln` 编译

也可以直接运行已编译的 `485扫描.exe`（位于项目根目录或 `bin\Debug`、`bin\Release` 下）。

## 使用说明

### 1. 串口方式

1. 打开软件，切换到「串口」选项卡。
2. 在「端口」下拉框中选择串口（下拉时会自动刷新可用串口列表）。
3. 选择波特率（1200 / 2400 / 4800 / 9600 / 14400 / 19200 / 56000 / 115200，默认 9600）。
4. 点击「打开」，状态栏提示“串口已打开！”。
5. 设置「输入寄存器ID」和「延时时间」。
6. 点击「开始」开始扫描，点击「停止」可随时中断。

> 打开串口后，「网口」选项卡会被禁用，需要先关闭串口才能切换。

### 2. 网口方式

1. 切换到「网口」选项卡。
2. 选择「协议类型」：
   - 选择 `TCP Server` 时，「网络地址」会自动填入本机 IPv4 地址；该地址必须是本机 IP，否则会提示“输入地址不是本机IP！”。
   - 选择 `TCP Client` 时，请手动填写目标设备/串口服务器的 IP。
3. 填写端口号（默认 8080）。
4. 点击「连接」，状态栏提示连接结果（`TCP Server` 无客户端时开始扫描会提示“当前无客户端连接！”）。
5. 设置「输入寄存器ID」和「延时时间」，点击「开始」扫描。
6. 点击「断开」结束网络连接；断开时会同时停止扫描。

> 连接网络后，「串口」选项卡会被禁用，需要先断开网络才能切换。

### 3. 其他按钮

- **清除数据**：清空接收区文本框。
- **停止**：停止正在进行的扫描。

## 通信协议说明

扫描时逐个地址发送标准 Modbus RTU「读保持寄存器（功能码 0x03）」请求，请求读取 1 个寄存器：

| 字节序号 | 内容 | 说明 |
| --- | --- | --- |
| 0 | 从站地址 | 扫描过程中从 `1` 递增到 `255` |
| 1 | `0x03` | 功能码：读保持寄存器 |
| 2 | 寄存器地址高字节 | 来自「输入寄存器ID」 |
| 3 | 寄存器地址低字节 | 来自「输入寄存器ID」 |
| 4 | `0x00` | 寄存器数量高字节 |
| 5 | `0x01` | 寄存器数量低字节（读 1 个） |
| 6 | CRC 低字节 | CRC16（Modbus） |
| 7 | CRC 高字节 | CRC16（Modbus） |

- CRC 采用 Modbus 标准 CRC16（多项式 `0xA001`，初值 `0xFFFF`，低字节在前）。
- 发送间隔由「延时时间」控制，即每次请求之间的时间间隔；在 485 总线上建议根据设备响应速度适当加大，避免多设备应答冲突。
- 接收数据在最后一帧数据到达约 20 ms 后统一读取并显示（十六进制，字节间以空格分隔），随后从该帧首个字节解析出地址并追加显示。

## 注意事项与已知限制

- 扫描仅覆盖从站地址 `1`~`255`（地址 `0` 为广播地址，不参与扫描）。
- 程序不做应答超时/重发判断，只是按设定间隔持续发送请求并显示收到的原始数据；离线地址不会显示任何内容。
- 串口接收依赖 `DataReceived` 事件 + 20 ms 定时器合并数据，若设备应答被拆分成间隔较大的多段，可能被分成多行显示。
- `TCP Server` 模式下程序只保留最近一次连接的客户端数据流用于发送扫描帧，多客户端同时连接时行为不可预期。
- 波特率列表中的 `56000` 为非标准值，部分串口芯片/驱动可能不支持。
- 「输入寄存器ID」实际作为 Modbus 请求中的寄存器地址使用（0 基地址），请根据设备手册确认是否需要做 ±1 偏移。
- 接收区数据量很大时（长时间扫描）界面刷新会变慢，建议及时点击「清除数据」。
